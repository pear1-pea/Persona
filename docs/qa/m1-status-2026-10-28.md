## Changes and discovered failure

- Repository 串行协调选择、刷新、初始化、生成注册和完整删除操作。
- 请求保留首个停止原因及所属模型，避免迟到事件触发云端回退或更新其他模型。
- Native 释放失败时保留资源身份，后续删除必须先成功重试释放。
- 临时失败使用退避；用户取消不计失败；重新选择当前模型支持明确重试。
- 测试调度器可控，同时保留真实 IO 并发案例，避免 Mockito 并发配置竞态。

真机发现 1.5B 的 `tokenizer.txt` 含 303,056 个 CRLF。文件哈希虽然匹配原 manifest，
仍在 MNN tokenization 中触发 `unordered_map::at: key not found` 和 SIGABRT。
其 CRLF 转 LF 后与可运行的 0.5B tokenizer 字节完全一致。
[固定版本的 MNN 源码](https://github.com/alibaba/MNN/blob/d407447ed56c4121a11ccbd266dc184ca1ead0c2/transformers/llm/engine/src/tokenizer/tokenizer.cpp)
使用 `getline` 读取词表且直接查表，未清除行尾 CR。

App validator 和打包工具现会拒绝 CRLF 文本 tokenizer，要求恢复 LF 并重建 manifest，
不静默修改安装包。新增回归测试先在旧实现失败，再在修复后通过。
真机使用单独修复的 1.5B 副本，版本 `1.0.0-m1-lf`；原下载文件保留。
测试还增加了隔离模型预清理及 instrumentation 状态输出，支持中断后重跑、保留阶段记录。

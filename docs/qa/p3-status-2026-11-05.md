# P3 集中验收记录

日期为 2026-11-05，分支为 `codex/p3-memory`，基于 P2 的 `965f69d`。
P2 的手动记忆无法覆盖受控候选、来源变化和相关证据选择。P3 在现有 Room、Auth、
Hybrid 与聊天链路内补齐这些职责，模型内容质量独立记录。

## 交付与默认策略

- 候选功能默认关闭。明确“记住”表达和主动选择消息提供规则或手动入口。
- 候选逐条确认，支持原文、编辑、新建或修订、忽略、独立云端权限及到期日期。
- Room v9 保留来源哈希、任务状态、幂等身份、并发 revision 和摘要多来源。
- 原消息变化、删除、账号切换和授权撤回会使相关任务失效。
- 默认当前 Persona 和本地使用。云端提取与正式记忆的云端使用分别授权。
- 中文关键词排序取代单纯最近记录，维持四条和 1,200 UTF-16 单元预算。
- 摘要采用最多 400 UTF-16 单元的原文摘录，限定当前 Persona 本地使用。
- 自动候选服从历史排除状态，主动重新选择来源是独立明确操作。
- 本地模型提取只作为 Debug 实验入口，默认关闭，不能自动写入正式记忆。
- 到期日期按填写日期的 UTC 零点解释。Embedding、后台持续整理和 ANN 保持条件式待办。

## 检索与资源

新增自然茶偏好问法回归后，固定检索样本为十例。实际 Kotlin 排序完全匹配为 10/10，
最近记录基线为 3/10，host FTS4 原始查询为 4/10，Kotlin 分词 FTS4 为 10/10。
样本包含两字词、别名、混合语言、否定原文、旧相关记录、无证据和权限边界。
这些是小型合成案例，不代表通用语义召回能力。

独立真机验收在 1,001 条 Room 记录中检索旧相关记忆，预先声明 p95≤250ms、
GC 后保留 Java 堆增量≤16MiB。五次预热、三十次测量得到 final6 p50=71.29ms、p95=115.21ms，
GC 后增量为零，满足该设备、该 fixture 的预算。零表示本次 GC 后差值未增加，
不表示过程中没有分配、没有峰值内存或所有数据规模均满足预算。

另有 601 条实际仓库探索测量，0.5B 环境 p95≈97.22ms，1.5B 环境 p95≈86.45ms。
当时进程 VmHWM 分别约 1,059,804kB 和 1,438,456kB，包含已加载模型和此前工作负载，
属于进程高水位，不能解释为检索本身的额外峰值。

## 模型内容质量

对现有 Qwen2.5 0.5B 和 1.5B 各运行六条固定合成样本，共十二次实际 MNN 提取调用。
参数为 temperature=0、topP=0.8、maxTokens=256。样本覆盖偏好、否定、目标、回忆提问、
虚构和冲突偏好。0.5B 六次均未通过严格 JSON/来源解析，1.5B 一次被拒绝、五次完成解析。
其中提问和虚构样本仍产生错误候选。严格参考内容完全一致为 0/12，这一指标包含前缀、
类型或选段差异，不能宣称通用模型准确率为零，也不能把解析通过视为语义正确。

据此保留规则与手动入口，本地模型提取仅留 Debug 实验。错误输出拒绝写入，所有合法
模型候选仍须用户确认。实际云端样本在约 1,655ms 内完成，获得预期偏好候选，授权撤回
后没有新增请求。单条云样本不足以证明全面质量，服务端实际模型 revision 未由响应
协议返回，报告使用代理配置身份，不能据客户端配置宣称服务端模型版本。

本轮没有要求新的人工打分，也没有把 P2 历史质量缺陷改为通过。

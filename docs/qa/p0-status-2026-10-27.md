## Known limitations

- Windows 从 GitHub 下载 MNN 时发生 TLS 失败；单独验证 codeload 时发生超时，
  部分文件被哈希校验拒绝。Windows 构建使用本机已有且干净的固定版本 submodule。
  尚未证明 Windows 网络下的自动下载回退可用。
- 首次远程 CI 在 `setup-android@v3` 默认安装旧 `tools` 包时失败，尚未进入编译。
  根据 [action 输入定义](https://github.com/android-actions/setup-android/blob/v3/action.yml)，
  Linux 和手动 Windows job 均显式设置 `packages: platform-tools`，
  平台、NDK、CMake 仍由后续步骤按固定版本安装。该修正不改变 Android 源码。
- MNN 可选 KleidiAI 依赖下载也受网络影响；必须在性能报告中注明实际启用状态，
  不能把不同构建配置的吞吐量直接比较。
- 首次完整验收脚本发现多个 `python.exe` 导致命令选择失败；已修正，保留失败记录。
- `npm audit --json` 报告 1 个 high 告警，涉及现有 Zod 3 依赖的
  [oversized collections 内存消耗问题](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5)。
  注册表建议升级至 Zod 4，属于 major 升级；本轮未执行 `audit fix --force`。
  输入体积限制不能代替依赖漏洞的修复验收；公开发布前需单独修复并回归校验行为。
- 第一次 Mac 源码包携带 AppleDouble 文件，导致 Android 资源编译失败；
  已重新生成干净源码包，隔离副本中的元数据被移至 ignored build 目录。
- 远程 CI 需要包含新增源码、测试、工具和 workflow 的提交。
  pear 随后已授权提交到 `codex/p0-baseline`、推送并创建 Draft PR；
  远程结果以该 PR 的检查状态为准，不合并 master。

P0 的最终验收门要求 Windows 与 CI 都通过。本报告记录 Windows 验收结果；
后续 CI 结果以 Draft PR 的检查状态和日志为准。

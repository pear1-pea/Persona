# 真实 LLM 人工评审协议 human-pairwise-v1

2026-11-04，pear 选择停止 P2 的追加人工评分。本协议保留用于后续模型质量研究，
P2 本轮以工程边界与可恢复性收尾。v5 输出维持未评审状态，既有评分和已发现缺陷保留。
对外描述应对应具体的权限、数据与恢复验证范围。

这是待执行的评审流程，不是已完成的模型验收。

1. 在 dev 上固定基线与候选各自完整配置、模型工件或服务模型 revision、runtime、
   量化、实际参数、设备和权限过滤实现。先跑应用边界测试，权限失败不得送云。
   若服务端不支持 seed 或某参数，记录 unsupported 和实际值，不能标成可复现。
2. 每条主观案例独立初始化；仅传入授权后的证据、角色设定和给定多轮 messages。
   不将期望或 rubric 发给生成模型。按计划每案例每配置运行 3 次，记录失败、取消、
   超时与重试，不只挑最好输出；运行过程中不改变配置。
3. 输出 A/B 随机打乱，每次保存私下映射供审计。评审员只看到用例、允许证据、
   rubric 与匿名输出。未盲测须标注限制；仅有一个模型配置的人工审查可记录，
   但不能产生“胜过基线”的结论。
4. 对 must 逐项判定，对 must_not 逐项标记违规。按用例 dimensions 为每个输出
   给 0/1/2 分：0 = 明显失败，1 = 部分达到且有具体缺陷，2 = 达到该项要求。
   不用字面关键词代替对事实、冲突澄清和风格的判断。
5. 记录 A/B/tie/both_fail/unresolved、理由与评审者。`both_fail` 表示两边均不合格且
   结论明确；`unresolved` 表示尚无法判断。单配置用 A/fail/unresolved，明确失败使用
   `fail`。A/B 表示相对偏好，是否达到要求仍须查逐项评分。边界/隐私/删除违规单列。
   评审有分歧或关键违规由第二位人工复核；自动裁判只能提示抽查，不能独立定论。
6. 冻结配置后再跑 heldout，记录逐案例三次结果、胜/负/平/未决、失败数和违规数。
   人工检查全部 14 条，尤其检查未知、冲突、恶意模板、删除与跨角色的行为。
   这个小型合成集只能发现回归，不能估计真实人群体验或证明广泛泛化能力。

使用 `templates/llm-run.v2.json` 复制成每次独立记录；空/null 表示未测，不是零错误。
`case_entry_template` 是填写说明，复制到 cases 后补齐每个 case/repetition。
must_checks 的每项记录准则与 pass/fail，dimension_scores 用用例中的维度作 key。
真实运行开始才填写 started_at；全部评完才写 completed_at 与 summary。
离线 `review_packet.py` 校验实际运行记录的完整性并生成匿名 A/B 页面与待填评分表，
不会自动填写人工评分或宣称主观质量通过。旧模板与新批量回执格式分别保留版本，
不可把空值或仅下载过的评分表视为完成评审。

页面导出的 JSON 可用 `check_human_review.py` 对照原 `human-review.json` 和
`private-mapping.json` 检查。它拒绝漏项、改动 rubric、错误类型或对 unsupported 评分；
逐项保留人工报告的缺陷，只在填写完整后解盲。关键边界违规或未决分歧按本协议复核。
输出 `requires_owner_assessment` 仍不是自动批准发布，也不代表工具重新判断了内容质量。

新包为每次生成分配独立的 `packet_id`，模板、页面导出及私有映射必须属于同一个包。
`private-mapping.json` 使用 `{"packet_id": "...", "mapping": [...]}`，校验器拒绝其他包
的映射，以及缺失或更改包身份的提交。浏览器仅恢复同包、同输入及同案例顺序的缓存。
包身份不公开配置映射，也不在页面放置可用于穷举小型映射的摘要。

兼容路径明确保留无 `packet_id` 的冻结模板、提交及旧版列表映射。新旧绑定格式不能混用。
新脚本遇到旧版无身份表单时仅提供下载，不读写未绑定的缓存。已有冻结页面及其内嵌脚本
保持原样，补充评审材料另存并记录来源，不通过重新生成页面改变匿名顺序。

`unresolved` 即使填写第二位评审者也始终未完成，不解盲。人工复核须填写实际已解决的
`winner`；保留澄清和复核依据。比较主评审者及复核者是否独立时，两边姓名均去除首尾空白。

未来页面展示实际生成的 Persona `name`、`backstory` 和 `traits`。当前 M5 parser 仅读取
`persona_profile.name` 与 `personaBackstory`，实际 Room fixture 没有插入 trait，因此
`traits=[]`。`language/style/fiction` 等元数据未作为独立字段传入模型，页面不将其值冒充
额外生成输入。人格约束仍以实际 backstory 及应用 Prompt 为准。

旧表单只有 unresolved；仅在原评审者明确澄清后，才能将其结论另存为 both_fail。
保留原下载文件及哈希、澄清依据和逐项变更记录，不覆盖原表单、rubric 或匿名映射。
明确失败本身不要求第二人解决分歧，关键违规仍按本协议复核。缺姓名或理由须由
原评审者补充，工具不代填，也不把明确失败改成通过。

输出仅使用合成数据。优先在忽略的 `results/` 中保存本地工件引用与配置快照，
不向日志输出 Authorization、完整 Prompt、完整 Response 或原始记忆。
需要人工看完整输出时使用本地受控查看工件，勿提交、自动上传或混用真实聊天。
最终记录应明确哪些检查来自参考 oracle、哪些来自应用实测、哪些来自人工评审。
